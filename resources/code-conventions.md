# Coding Conventions

This is the canonical entry point for coding conventions in a consuming project. Replace or extend
this scaffold with the project's language, framework, naming, formatting, error-handling, generated
code, and test-organization rules.

Until project-specific rules are recorded:

- Follow the standard formatter and linter for each language.
- Prefer explicit interfaces and narrow responsibilities.
- Keep behavior changes covered by tests.
- Do not edit generated code; regenerate it from its source.
- Treat established architecture and design documents as authoritative.

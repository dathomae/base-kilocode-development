# Architecture

This directory captures the overall organization of the system, especially for parts that are potentially longer lived:

- Schema definitions
- Service division
- Endpoint definitions
- Major system components
- Services that could exist in some form in post-v0 versions of the system

## Guidelines

- Architecture documents provide implementation guidance for things in concepts or requirements.
- Documents may include terminology not exposed to users or customers.
- When an internal term maps back to a user-visible term, that mapping should be given explicitly.
- Break documents into logically related pieces to facilitate incremental review and use by agents.
- Concepts or definitions from [`../concepts.md`](../concepts.md) or [`../requirements/`](../requirements/) SHOULD NOT BE REPEATED; reference them instead.

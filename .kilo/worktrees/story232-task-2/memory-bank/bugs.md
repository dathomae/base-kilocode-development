# Bugs

| Bug Description                                 | Longer Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Accepting internal IDs as input parameters      | Internal database IDs (like element_id, ns_fam_id, etc.) should never be accepted as input parameters in APIs or CLIs. Dependencies should always be specified by their human-readable names, and IDs should be resolved internally by the system.                                                                                                                                                                                                                                                         |
| Exposing internal database IDs in API endpoints | API endpoints for creating or updating resources should never expose or require internal database IDs (like `ns_id`, `category_id`, etc.) in the request payload. Instead, the API should accept human-readable identifiers (like names) and resolve them to internal IDs internally. This prevents API consumers from needing to know internal database state and improves API usability.                                                                                                                 |
| Frontend types storing database IDs             | Frontend type definitions (like `TreeNode` in MetadataTree.tsx) should never include internal database ID properties (`ns_fam_id`, `ns_id`, `category_id`, `element_id`). These implementation details should not leak into the UI layer. Instead, frontend types should use human-readable names for uniquely identifying nodes in a hierarchy (e.g., `ns_fam_name`, `ns_name`, `category_name`). The combination of parent names provides a unique path to any node without exposing database internals. |

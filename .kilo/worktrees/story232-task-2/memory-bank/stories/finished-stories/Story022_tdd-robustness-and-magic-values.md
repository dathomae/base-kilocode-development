# Story 022: TDD Robustness & Magic Value Removal

## Goal
This story addresses the removal of magic values from the metrics service and updates the testing approach to prevent 'dummy implementations' that hardcode shortcuts to pass tests. We require true database-driven validation, fuzzing for date/key inputs, and strict repository mocking contracts to guarantee the integrity of TDD iterations.

## Tasks
1. Update `lessons-learned.md` to establish the new global policy on avoiding magic values and strictly enforcing repository-layer checks over surface-level API schema checks in test suites. - Completed
2. Refactor 	test_services.py to use dynamic test inputs (UUIDs, runtime randomization) explicitly checking database calls or mock contracts instead of testing surface-level error responses generated by magic values. - Not Started

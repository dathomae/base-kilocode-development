# Story 043C: Purge Store Abstraction

## 1. Overview
The `store/` package is a repository-pattern abstraction generated by earlier LLMs. It introduces a `Store` interface, an in-memory implementation, and an 833-line `rdbms.go` that manually maps go-jet models to its own struct types — all of which contradict the adopted Services Pattern where domain-adjacent `_sql.go` files query tables directly and call `ExecuteBitemporalMutation` for writes.

The real infrastructure (`mutation.go`, `locks.go`, `constants.go`, `temporal_expressions.go`) currently lives inside `store/rdbms/` but logically belongs in `serde/rdbms/`, which is the RDBMS serialization/deserialization boundary. This story purges the repository-pattern shell and relocates the infrastructure, then corrects every documentation reference that would cause future LLMs to hallucinate repository-pattern code.

**Why this matters:** LLMs read these documents as authoritative guidance. Every reference to "Repository layer," "Data Access Layer," "Store," or "Close and Insert" in the memory bank actively steers new code toward the wrong architecture. Purging the abstraction means purging the hallucination source.

## 2. Requirements

* Update the `package` declaration from `package rdbms` to match the target package.
* If `serde/rdbms` already has a different package name, reconcile — the infrastructure files must share the package with the generated code or use a sub-package if necessary.

### 2.2 Code Deletion: `store/`
Delete the following files entirely:

| File | Reason |
|---|---|
| `store/interface.go` | Repository-pattern `Store` interface — contradicts Services Pattern |
| `store/memory.go` | In-memory `Store` implementation with duplicate domain structs |
| `store/rdbms.go` | 833-line repository implementation with manual mapping tax |

Delete the `store/` directory once empty.

### 2.3 Handler Stubbing and Import Removal
The handlers (`families.go`, `namespaces.go`, `categories.go`, `elements.go`) currently depend on `store.Store` types and the in-memory implementation. Since the `store/` package is being deleted and no domain services exist yet to replace it, the handlers must be **stubbed** to preserve the API route structure without a backing implementation.

**For each handler file in `src/backend/handlers/`:**
1. Remove the `chronocone/backend/store` import.
2. Remove any `store.Store` field from the handler struct (or replace the struct with a minimal placeholder).
3. Replace every handler method body with:
   ```go
   http.Error(w, "not implemented: pending domain service migration (Story 043C)", http.StatusNotImplemented)
   ```
4. Preserve the handler function signatures and route registrations so the OpenAPI contract remains structurally intact.

**For `src/backend/main.go`:**
1. Remove the `chronocone/backend/store` import.
2. Remove the `NewRdbmsStore` / `NewMemoryStore` initialization.
3. Instantiate the stubbed handlers without a store dependency.

| File | Current Import | Action |
|---|---|---|
| `src/backend/main.go` | `chronocone/backend/store` | Remove import, remove store initialization |
| `src/backend/handlers/families.go` | `chronocone/backend/store` | Stub all methods with 501 |

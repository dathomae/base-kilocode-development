# fastparquet Quickstart

You may already be using fastparquet via the Dask or Pandas APIs. The options available, with `engine="fastparquet"`, are essentially the same as given here and in the API docs.

## Reading

To open and read the contents of a Parquet file:

```python
from fastparquet import ParquetFile

pf = ParquetFile('myfile.parq')
df = pf.to_pandas()
```

The Pandas data-frame, `df` will contain all columns in the target file, and all row-groups concatenated together. If the data is a multi-file collection, such as generated by hadoop, the filename to supply is either the directory name, or the "\_metadata" file contained therein - these are handled transparently.

### Investigating Metadata

Before loading, you may wish to investigate the meta-data associated with the data, for example, to choose which row-groups and columns to load. The following properties are available:

| Property     | Description                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------- |
| `columns`    | List of available column names                                                                |
| `count`      | Total number of rows                                                                          |
| `dtypes`     | Expected output types for each column                                                         |
| `statistics` | Max/min/count of each column chunk                                                            |
| `info`       | Summary dictionary                                                                            |
| `cats`       | Possible values of each partitioning field (for hierarchical directory-partitioned structure) |

You can get a deeper view of the parquet schema with:

```python
print(pf.schema)
```

### Selective Column Loading

You may specify which columns to load, which of those to keep as categoricals (if the data uses dictionary encoding), and which column to use as the pandas index. By selecting columns, we only access parts of the file, and efficiently skip columns that are not of interest.

```python
# Load specific columns, keeping col1 as categorical
df2 = pf.to_pandas(['col1', 'col2'], categories=['col1'])

# Or specify the number of expected labels for that column
df2 = pf.to_pandas(['col1', 'col2'], categories={'col1': 12})
```

If the data originated from pandas, the categories will already be known.

### Filtering Row Groups

Row-groups can be skipped by providing a list of filters. There is no need to return the filtering column as a column in the data-frame. Note that only row-groups that have no data at all meeting the specified requirements will be skipped.

```python
# Filter to rows where col3 is in [1, 2, 3, 4]
df3 = pf.to_pandas(['col1', 'col2'], filters=[('col3', 'in', [1, 2, 3, 4])])
```

**Note:** Row-level filtering was added in version 0.7.0.

## Writing

To create a single Parquet file from a dataframe:

```python
from fastparquet import write

write('outfile.parq', df)
```

The `write` function provides a number of options. The default is to produce a single output file with row-groups up to 50M rows, with plain encoding and no compression. The performance will therefore be similar to simple binary packing such as `numpy.save` for numerical columns.

### Write Options

| Option              | Description                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `compression`       | Compression algorithms (typically "snappy" for fast, but not too space-efficient), which can vary by column                                                                                  |
| `row_group_offsets` | The row-group splits to apply, which may lead to efficiencies on loading if some row-groups can be skipped. Statistics (min/max) are calculated for each column in each row-group on the fly |
| `file_scheme`       | Multi-file saving with `"hive"` or `"drill"`: directory-tree-partitioned output with a single metadata file and several data-files                                                           |
| `append`            | Append to existing data sets with `append=True`, adding new row-groups. For "hive"-partitioned data, `append="overwrite"` replaces partitions where new data are given                       |

### Example with Options

```python
write('outdir.parq', df,
      row_group_offsets=[0, 10000, 20000],
      compression='GZIP',
      file_scheme='hive')
```

## Common Patterns for Time Series Data

For time series data storage, consider these patterns:

### Writing Time Series

```python
from fastparquet import write

# Write with partitioning by date column
write('timeseries.parq', df,
      partition_on=['date'],
      file_scheme='hive',
      compression='SNAPPY')
```

### Reading Time Series with Filters

```python
from fastparquet import ParquetFile

pf = ParquetFile('timeseries.parq')

# Filter to specific date range
df = pf.to_pandas(
    columns=['timestamp', 'value', 'metric_id'],
    filters=[('date', '>=', '2024-01-01'), ('date', '<=', '2024-12-31')]
)
```

### Iterating Over Large Datasets

For large datasets, iterate by row-groups to manage memory:

```python
from fastparquet import ParquetFile

pf = ParquetFile('large_timeseries.parq')

for row_group_df in pf.iter_row_groups(filters=[('date', '>=', '2024-01-01')]):
    # Process each row-group separately
    process_batch(row_group_df)
```
